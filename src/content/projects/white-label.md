## Контекст

После M&A-сделки МТС Линк и Vinteo (видеоконференции, on-premise) клиентам Vinteo нужно было дать единое приложение чатов и встреч под их брендом — «Vinteo Чаты». Приложение МТС Линк — это веб-хост с микрофронтендами, десктоп, iOS и Android. Механизма брендирования не было, кроме админки коробочной версии для встреч и авторизации: логотипы, один фирменный цвет, название организации, контакты поддержки.

## Задача

Пользователь партнёра не должен видеть элементов МТС Линк ни до, ни после авторизации — на всех платформах. Партнёру нужны название, логотип, акцентные цвета, ссылки на свою базу знаний и загрузку приложения, свои контакты поддержки. Механизм должен быть пригоден для других организаций и для новой дизайн-системы, а при недоступности конфигурации интерфейс обязан оставаться рабочим. Срок — квартал.

## Что сделал

### Разделил «быстрое брендирование» и «полный white label»

Полный white label — смена дизайна всех продуктов, домена, локализации — требует единой дизайн-системы, которая внедрялась параллельно. Для запроса партнёра достаточно заменить акцентные цвета, логотипы, название и ссылки. Решил идти быстрым путём: без админки брендирования (для одного-двух клиентов конфигурацию можно собрать вручную), но так, чтобы механизм пережил переход на новую дизайн-систему.

### Спроектировал конфигурацию в два шага

- Хост не имеет собственных заголовка, favicon и логотипа — всё подставляется из конфигурации организации; по умолчанию — набор МТС Линк.
- До авторизации приложение запрашивает версию и путь к бренд-ассетам на CDN: favicon, логотип, стили, шрифты. Ассеты версионируются.
- После авторизации — данные бренда: идентификатор, заголовок вкладки, тема, ссылки на базу знаний и скачивание десктопа, почта и телефон поддержки. Значения кэшируются локально, чтобы при перезагрузке страницы бренд применялся сразу.
- Новых контрактов API нет — используется существующий механизм конфигурации. Через него же для бренда партнёра отключаются функции, которых у него не должно быть: вход по QR, импорт из Telegram, виджет чата с поддержкой, ИИ-помощник, остальные продукты платформы в навигации.

### Записал fallback как критерии приёмки

- CDN недоступен (403/404) → логотип по умолчанию, приложение не падает.
- Некорректный цвет (не HEX) → цвет по умолчанию.
- Домен без настроек брендинга → стандартный бренд.
- Загрузка конфигурации не блокирует отрисовку больше **200 мс**.

### Десктоп и мобильные

Десктоп — отдельная сборка с зашитым брендом: название приложения, иконки и иконка трея, заголовок окна, схема deeplink, сервер по умолчанию; бренд читается из встроенной конфигурации без запроса к серверу, сборки публикуются автоматически. На iOS и Android определил минимальный набор экранов: иконка, экран запуска, вход, список чатов, чат, список встреч, карточка встречи, экран перед входом и экран звонка, системные диалоги разрешений. Deeplinks ведут на домен партнёра, переход в чат или встречу по ссылке открывает его приложение.

### Собрал общий документ по зонам ответственности

Таблица «что хранится и управляется у нас, что у партнёра»: домен, аккаунты, публикация в сторах, видеоконференции, запись встречи — у партнёра; чаты, встречи, роли, продуктовая логика — у нас. План внедрения: нулевой инсталл → тестовая группа → сбор обратной связи → передача партнёру для публикации MVP.

## Результат

Механизм реализован для веба, экрана авторизации, встреч и десктоп-версии; проведены продуктовая проверка и дизайн-ревью, сценарий проверен на домене партнёра. Для iOS и Android записаны демо пользовательских сценариев, презентация «Vinteo Чаты 1.0» показана клиентам.

Метрики CX и бизнеса не измерялись — задача была инфраструктурной. Качественный эффект: у партнёра появился брендированный продукт чатов и встреч без отдельной кодовой базы, а у платформы — механизм брендирования, который переиспользуется для новой дизайн-системы и других организаций.

## Чему научился

Самая дорогая часть white label — не замена логотипа, а решение, каких функций у бренда партнёра не должно быть вовсе. Список «убираем в первой версии» сэкономил больше времени, чем любая техническая оптимизация.
